# 아키텍처 제안

## 개요
- 클린 아키텍처 지향: Presentation(React) / API(Flask 또는 FastAPI) / Domain(파싱/인덱싱) / Infra(SQLite) 분리
- 배치성 인덱서 + 온라인 조회 API 이원화

## 선택지
- 기본: Flask 유지(현행 연속성) + SQLite FTS5 도입
- 대안: FastAPI + Pydantic(타이핑, 스키마 검증 용이)

## 권장 구성
- 백엔드
  - 레이어: api(라우터) / services(파싱, 인덱싱, 검색) / repos(DB) / core(도메인, 유틸)
  - DB: SQLite + FTS5 가상 테이블(`emails_fts`)로 제목/보낸이/본문 인덱싱
  - 잡: 초기 풀스캔 인덱싱, 증분 인덱싱(해시/mtime 기반), 수동 재생성
- 프론트엔드
  - 라우팅 단순화, 상태: React Query 또는 경량 상태관리(Zustand)
  - 접근성/키보드 내비게이션, 큰 리스트 가상 스크롤(Optional)
- 보안/운영
  - 경로 정규화 + 루트 프리픽스 강제
  - DOMPurify 화이트리스트 유지
  - 상태/진행률/로그 뷰 제공

## 구성도 (요약)
- React UI → Axios → API 서버(`/api/...`) → Service(파싱/검색) → SQLite(메타/FTS)
